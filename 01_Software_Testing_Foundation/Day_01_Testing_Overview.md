# Day 1: Software Testing Overview

## 1. Introduction to Software Testing
* **Definition:** The process of evaluating a software application to verify it meets customer requirements and is defect-free.
* **Why it is Necessary:**
  * Prevents critical issues from reaching the customer.
  * Protects the company's reputation and brand trust.
  * Ensures the software is secure, reliable, and performs well.

## 2. Manual Testing vs. Automation Testing
* **Manual Testing:** A human tester physically interacts with the software like a real user to find bugs.
  * *Best for:* Brand new features, exploring the app, and checking if the user interface "feels" right.
* **Automation Testing:** Using code and specialized tools (like Selenium) to execute tests automatically.
  * *Best for:* Repetitive tasks, saving time, and verifying old features still work after a new update.

## 3. The Defect Terminology Flow
* **Error (Mistake):** A human mistake made by a developer while writing code.
* **Defect (Bug):** The flaw found by a QA Tester internally, before the software is released.
* **Failure:** The breakdown experienced by the Customer when using the software in the real world.
* **The Flow:** Error ➔ Defect ➔ Failure.

## 4. Why Software Has Defects & The Cost of Fixing
* **Causes of Defects:** Human error, miscommunication of requirements, tight deadlines, and complex code.
* **The Cost Rule:** The later a defect is found in the development cycle, the more expensive it is to fix.
  * *Early discovery:* Costs almost nothing (fixing a typo in a document).
  * *Late discovery:* Costs thousands (emergency developer overtime, angry customers, lost sales).

## 5. Verification & Validation (V&V)
* **Verification:** Checking documents, designs, and code without running the software. It asks: *"Are we building the product right?"*
* **Validation:** Testing the actual, working software. It asks: *"Are we building the right product?"*
* **Why it is Necessary:** Verification ensures the software is built correctly according to the design documents, while Validation ensures the final product actually satisfies the client's original business needs.

## 6. Role of a Tester
* The QA Tester is the gatekeeper of quality.
* **Core Responsibilities:**
  * Analyze business requirements.
  * Design and execute test steps.
  * Identify defects and report them to developers.
  * Act as the bridge between the development team and the final user.
