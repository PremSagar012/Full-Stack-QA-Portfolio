# Day 2: SDLC Phases & Waterfall Model

## 1. What is the Software Development Life Cycle (SDLC)?
* **Definition:** The structured, step-by-step process used by software teams to design, develop, test, and deploy high-quality software.
* **Why it is Necessary:** It provides a clear roadmap. Without it, developers would just guess what to build, resulting in chaotic, buggy, and expensive projects.

## 2. The 6 Core SDLC Phases
Every software project generally follows this specific order:
1. **Requirement Gathering & Analysis:** Business Analysts figure out exactly what the client wants the software to do.
2. **Design:** Architects plan how the software will look and function (databases, user interfaces, system architecture).
3. **Development (Coding):** Programmers write the actual code to build the application.
4. **Testing:** QA Engineers test the compiled code to find defects and ensure it matches the requirements.
5. **Deployment:** The finished software is released to the live server for customers to use.
6. **Maintenance:** The team fixes any post-release bugs and provides ongoing updates or new features.

## 3. The Waterfall Model
* **Meaning:** The oldest and simplest SDLC model. It is a linear, sequential approach where you must 100% finish one phase before you can "flow down" to the next one (like a waterfall).
* **How it works:** You cannot start Designing until Requirements are entirely locked in. You cannot start Testing until Development is entirely finished.
* **Pros:** Very easy to manage, highly structured, and excellent for small projects with fixed, unchanging rules.
* **Cons:** Highly rigid. If a customer wants to change a requirement while you are in the Testing phase, it is incredibly expensive and difficult to go backward. Testing happens very late in the process.
